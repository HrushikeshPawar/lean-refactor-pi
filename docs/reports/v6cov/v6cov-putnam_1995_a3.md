## 5. What the model could have done better

1. Skip the long first-principles derivation. The reference proof was in the packet and the model's own turn 2 reviews it ("The reference proof: for each i ..."). It spent 62K output tokens ($0.040, 7.4 min) before any tool call, about 10% of the run for nothing a probe could not have shown, and the first 32K were thrown away. A drafted proof compiled at turn 11 with only 5 failing drafts in between. Using `arena_probe` with `sorry` holes as a scratchpad would have given goal states at about $0.004 per turn.
2. Track the budget from numbers the harness gives. `arena_finish` returned `remaining_usd` each time and the continuation message carries it too, but the model kept re-estimating (5 of 5 notes under by $0.03-0.09) and called finish 8 times (7 refusals, $0.024 and 6.8 min). It could compute from the `spent` it receives in each continuation line, or wait for the continuation message.
3. Treat failing-draft heartbeats as partial. Turn 53 (and turn 91, 11,461 HB) show the number is not a cost of the finished proof.
4. Stop probing variants of the same hunk once it has been measured equal: #24 (hoist `h7D`) equals #22, #21 equals #19 + changed hE, #55 resubmitted at turn 83. Each repeat costs a $0.0035-0.0050 turn and the cache hit shows the draft was already known.
5. Use the strongest tail ideas earlier. The largest remaining single hotspot after #22 was the `convert` (312-429 HB, 13-19% of the total). It was attacked in turns 20, 32, 34, 43, 48, 56, 63, 69, 76 with small wins (#17 at turn 32 was the only big one, -95 HB). The profile at turn 22 already showed it as the top item. Two other measured wins in the tail (`rw .. ; beta_reduce`, `ring1`) were hotspot-by-hotspot discoveries that appear in the profile text as line costs, so an earlier systematic pass over "tactic X vs Y at each line" probes batched 2-3 drafts per call (it used 2 drafts in 40 of 63 calls, 3 in only 1) could cover more per dollar. Drafts per call averaged 1.67.

## 6. What the harness could have done better (sorted by likely score per dollar)

1. Do not compact when it cannot pay back at the real $0.5 cap (`models.yaml:54-56`, `tools/run_pi_budgeted.py:364-366`, `arena.ts` `session_before_compact` at the hook that sets `compacting = true`). The comment at `models.yaml:55` ("a compaction costs ~3 uncached requests (~$0.03)") does not hold at 500K: the whole turn prefix is sent uncached (about $0.07 here). Policy: if `remaining_to_finish_line < est_compaction_usd * 1.5`, or if the projected context at the soft cap stays below the window, defer. If Pi 1.0.4 lets `session_before_compact` return a cancel result, use that; otherwise set the trigger from a function of the current remaining allowance when writing `.pi/settings.json` (set `at_tokens` to the window minus reserve for a $0.5 run) or compute `compaction.enabled=false` once settled spend passes about 60% of the cap. Effect here: +$0.07 of probes (about 18 turns), roughly +0.1-0.2 pt at the tail rate plus no exposure to the failure chain.
2. Give the model the money, in numbers, in every tool result, and make the refusal text purely factual (`rules.ts:177-199`; `stateLine` in the same file). Add `spent_usd / remaining_usd / finish_line_usd` to the `[arena]` line appended to probe and profile results, and to `arena_state`. Remove "a micro-golf of the current proof will not close it" (`rules.ts:193`; false in this run: +7.5 pts came from golf inside r2 after the first refusal) and the clause "a repeat confirm is refused again unless a credited route opened or an attempt produced a goal state new to its route" (`rules.ts:196-197`; `finishAllowed` at `budget.ts:317-321` is budget-only). Same defect as in `v6cov-putnam_1964_b2` (12 refused finishes). Saves about $0.024 of finish turns here and the route-chasing the clause induces.
3. Make `error_loop` less terminal when money remains and the cause is deterministic (`arena.ts:1252-1273`, `MAX_ERROR_STREAK = 3` at line 22). Error text `Arena context bound exceeds the context window` came from our own guard and cannot clear by waiting 2 s and 4 s. Options: on that error and unspent allowance above the finish line, perform one forced compaction with the repaired path, or restart the agent from a fresh session seeded with the `arena-memory` message and the best proof (`arena.ts:696` `injectMemory`). At minimum count guard refusals separately from provider errors and do not stop before the 10% line.
4. Tighten the byte bound so it cannot exceed the real token count by 2.9x (`budget.ts:267-271`). `byteBound = bytes + 4096` assumes 1 token per byte; this run measures 2.85 bytes/token (1.42 MB / 498K). Any request without a valid prior (after a settled compaction, a failed turn or a resume) is refused from about 345K tokens, below the 500K trigger. Use the largest bytes-per-token measured so far in the run (floor, for example, 1.5) instead of 1.0. Lrx removes the compaction path from this; agent turns still use it. Related: the reserve estimate at the end was $0.0956 per request against $0.0036 actual (28x), because the estimate prices the whole context at the uncached $0.15 and 32K output tokens at $0.60; this matters only if the gate were ever the real $0.5 cap.
5. Keep, do not drop, the reasoning of a length-stopped turn (`arena.ts` `agent_before_settle` at 1243-1311 and the `context_edit` Pi writes for a `length` turn). Request 2 grew by 611 bytes over request 1, so 83.6K characters of reasoning vanished and was re-derived ($0.018). Options: keep the last N thousand characters of the truncated thinking as a tool-free assistant message, or add a factual line ("turn 1 stopped at 32,000 output tokens with no tool call; its reasoning is not in context"). Raising the limit to 64K (vqm) means one such turn costs up to $0.038 (7.6% of the cap); this run suggests the model does not need it for the first turn if the partial reasoning is kept.
6. Move cold verification out of `arena_finish` (`arena/campaign.py:2201-2218` `submission`, called at `arena.ts:1105-1107`). It ran 6 times in 8 calls (57-79 s each, 409 s total, 11% of the wall) and its result is used only for a label on the refusal path. Run it in the background lane when a verified best changes, and leave the refusal path to read the cached result. This costs no money but frees Lean time and shortens wall.
7. The history/turn-prefix split makes the history summary a stub (`session_before_compact` with a single agent turn). Where compaction is used, summarise the turn prefix only and skip the empty history request (two stubs, $0.008 here) or inject the packet digest. If memory is the real carrier, include the best candidate source in `arena-memory`, as the pilot reports describe. Minor dollars, but it also removes a wasted summarisation round on every compaction.
8. Reduce the per-profile bill: 11 profile calls at 22.5 KB each (about 70K uncached tokens, $0.0252 in turns plus cache replays). `trimProfile` keeps 12 entries (`rules.ts:215-224`); returning only the top 6-8 plus totals would cut about 40% of that. Low impact (about $0.01).
9. `arena_idea` bookkeeping: `idea_id "i2" is not a recorded idea; kept as a label` came after a draft and caused one extra `arena_idea` call (turn 22). Auto-create the idea on first use of a label so the model does not spend a call.
