Read this carefully

Method and boundaries

Interval accounting turns trace records into activity attribution. It does not turn the campaign into a process profile.

What the report counts

  • All 66 run directories under the audited V7/V8 scope; 63 have completed provider calls, three have no provider journal, and two more have unmatched request starts.
  • 6,111 matched request/response intervals in model latency percentiles and histograms.
  • 14 requests with no matched response have unknown completion time and are excluded from duration statistics.
  • 10 synthetic orphan responses are excluded; 887 inherited seeded-ledger events are excluded from run timing.
  • 13 campaign containers are excluded: .

What the hours mean

  • Observed activity span is the timestamp span from available run lifecycle, ledger, trace, cost, and health evidence. It is not exact process wall time or CPU time.
  • 45.03 summed run-hours describe total across-run activity spans; 25.15 h is the union on the global clock after concurrent runs overlap.
  • 35.14 h LLM (78.05%), 6.785 h exclusive tools (15.07%), 1.17 h setup/provider-free, 1.68 h after-final-trace, and 0.25 h interactive gaps partition the summed observed span.
  • Individual tool-call totals may overlap. The stacked composition uses tool-exclusive time; tool-by-tool totals use each call’s own start/end.
  • Run timeline intervals retain the source JSON’s Unix epoch seconds; hover/focus each interval to see exact ISO timestamps.
