### 1b. What each improvement changed (diffs of successive best proofs)

Baseline (original proof) proxy is 33.33 in every task (0 tokens saved, 0 HB saved, 3/3 versions). Axis rates: Core 1 token = 0.149 pt, 100 HB = 0.784 pt, a lost version = 11.1 pt (from packet/compaction summary). Reference sizes: Core 224 tok / 4252 HB; VC 851 tok / 11947 HB; CCS 251 tok / 3858 HB. Final: Core 83 tok / 202 HB (-63% / -95%); VC 160 tok / 1967 HB (-81% / -84%); CCS 85 tok / 263 HB (-66% / -93%).

**One structural rewrite delivers 73-83% of the total gain, then ~12-24 golf steps deliver the rest.**
- Core: first scored candidate (#2, 2 min, $0.017) deleted the `induction Hup` (case update_none / update_some, 45 lines) and replaced it with an equational proof: `rw [InitStatesUpdated Hinit, UpdateStatesUpdated Hup]` then `updatedStatesComm` + `updatedStatesUpdate`. 33.33 -> 76.99 (+43.7 of the final +52.7 = 83%); tokens 224->137, HB 4252->335. Next structural step (#4, 83.3): replace a 7-line `have hd : Disjoint ...` with an inline `rw [updatedStatesComm (by ...)]`. After that only micro steps: `exists (updatedStates ...)` -> `⟨_, rfl,...⟩`, `cases UpdateStatesUpdated Hup` to substitute instead of rw, hoist `have L := UpdateStatesLength Hup` (shared by 2 uses), `simp only` -> `simp`, `refine (comm ?_).symm ▸ ...`. The very last change (86.06 -> 86.07) just moves `unfold updatedStates` 1 line: -1 HB.
- VC: first scored candidate (#2, 5 min, $0.040): the 121-line reference (embed into `WithLp 2 V`, Cauchy-Schwarz, ball argument) replaced by a 31-line direct proof: pick x0 with f x0 != 0, `Continuous.inner'`, open neighbourhood from `Metric.isOpen_iff`, `ContDiffBump` test function `φ1 x • f x₀`, conclude with `Continuous.integral_pos_of_hasCompactSupport_nonneg_nonzero` vs `hg`. 75.8 (tok 851->370, HB 11947->3476). Then 21 more best-steps, mostly 1-line (each +0.01..1.5): `rw [funext_iff]; obtain` -> `Function.ne_iff.mp h₀`; `real_inner_self_nonneg'` simp wrappers removed; inline `hkey` into `by simpa only [inner_smul_right', Pi.mul_apply] using hg ...`; `rcases eq_or_ne` -> `by_cases h : x ∈ Metric.ball x₀ δ`; `exact`->`refine`. Biggest later jumps: 84.69 -> 86.18 (+1.5, #50, 8 lines: restructured the `hnn` nonneg obligation into the integral call, tok 241->206) and 87.89 (+0.4, hnn via `by_cases` ball).
- CCS: first scored candidate (#2, 4 min, $0.017): `exists ChoiceBisim` + nested `cases r` of 58 lines -> `refine ⟨@ChoiceBisim, .choice h, ?_⟩` (72.3). Then the key conceptual jump (#10, 79.1, 16 min): drop the hand-written 3-case case split for symmetry and prove only one simulation direction via `HomBisimilarity.symm_simulation` and a symmetric relation; subsequently `ChoiceBisim.rec (.choice ·.symm) (.bisim ·.symm)` (anonymous-constructor/dot-notation golf, tok 125->116), `rintro a b (hp | hb)`, `And.imp Tr.choiceL ChoiceBisim.bisim` and `(…).imp fun t => …` to fuse `obtain ⟨t,h⟩ ... ⟨t, ...⟩`. The final 86.44 move is one line (`And.imp_right … ∘ And.imp_left …` -> `And.imp Tr.choiceL ChoiceBisim.bisim`, -2 tokens).

Move classes (counting all best-so-far steps): whole-proof route change 1-2 per run; "dot-notation / lemma-combinator golf" (`.imp`, `And.imp`, `▸`, anonymous constructors, `⟨_, rfl⟩`) is the dominant micro class; shared-`have` hoisting and inlining single-use `have`s second; automation swaps (`simp` for `rw`) third. Heartbeat gains come almost entirely from the first rewrite (Core 335 -> 202 later; VC 3476 -> 1966; CCS 408 -> 263), later steps are token-driven (each token is 0.15 pt in Core, ~0.04 in VC because the reference is 851 tokens, so VC golfing is worth ~4x less per token -- yet DeepSeek still saved 210 tokens there).

## 2. Exploration

Data: ledger route/idea/probe/candidate events, cost-ledger finish/memory events, session compaction + arena-memory messages, trace tool calls.

**Draft volume.** Each `arena_probe` call batches several drafts (about 2.4 / 2.3 / 1.8 drafts per call: 75/31, 108/47, 81/44, which is cheap exploration per turn); every draft either compiles (becomes a candidate, auto-evaluated "full" on all 3 toolchains) or is logged as a probe (failed compile / sorry skeleton).
| run | drafts | compiled candidates | failed probes | compile rate | sorry skeletons | duplicate drafts |
|---|---|---|---|---|---|---|
| Core | 75 | 37 (incl. baseline) | 38 | 49% | 2 | 0 |
| VC | 108 | 63 | 45 | 58% | 0 | 0 |
| CCS | 81 | 28 | 53 | 35% | 6 | 0 |
Top first-error classes in failed probes: Core `unsolved goals` 14, `rewrite` pattern not found 5, `▸` result type 4; VC `unsolved goals` 10, `rewrite` pattern 8, app type mismatch 7, stuck typeclass 5; CCS app type mismatch 13, `grind` failed 7, `⟨...⟩` notation 6. Failures are mostly the price of golfing (aggressive anonymous-constructor / `▸` / `.imp` forms), not blind guessing: the 35-58% compile rate is on drafts that are deliberately 1-5 tokens from the incumbent. Zero duplicate drafts in all runs, i.e. no repeated work even across 3 compactions.

**Routes (harness fingerprints).** Core: r2 (the equational route, no induction) got 34 of 37 route events and the final best 86.07; r1 (original induction route) only got a baseline-compile + one cosmetic variant (#36, 33.49); r3 (`isDefinedApp` lemma family) 1 attempt, 80.25. VC: r3 (`mul_ne_zero`/`HasCompactSupport.mul`/`half_pos` family) 46 attempts, final best 88.25; r2 9 attempts (83.37), r4 (`IsOpen.preimage`/`Set.Ioi`) 8 attempts best 88.16, r5/support-measure compiled once at 85.05. CCS: r1 (original route label) 20 events incl. the final 86.44; r2 (`ChoiceBisim.rec`) 17 events, 1 scored attempt 86.32 (nearly identical result). Conclusion: the winning route was found in the first 2-5 minutes of every run and everything after was local search inside it. New-route attempts after finish refusals never beat the incumbent (Core r3 80.25, VC r5 85.05, CCS up-to route never compiled to a better proof).

**Ideas.** DeepSeek used the `arena_idea` tool rarely (VC 2 explicit calls); ideas are mostly auto-created labels: Core 6, VC 6, CCS 5 (+ ad-hoc labels like `grind-bodies`, `or_else_symm`, `upto_route`). Ideas without attempts: 0 in all runs. Quirk: in VC, candidates from 41-56 min are tagged idea i4 ("integrable-positivity family") although i4 was only declared at 57 min and these were really golf steps in route r3; so the harness' idea attribution understates how much of the late gain (87.36 -> 88.25, 41-54 min) was plain continued golf in the old route rather than new-idea work.

**Finish refusals** (rule: may finish only with <=10% left, and a refusal demands a compiled proof on a *new* fingerprint route). Each run tried to finish at 28-38% remaining at 39-48 min (Core 28%, VC 38%, CCS 32%) and was refused 4/3/3 times. What happened after refusal #1 (best at refusal / best at end / spend after):
- Core: 86.06 -> 86.07, $0.14 left, spent on 4 new ideas (i3-i6), 2 of them cosmetic; +0.01.
- VC: 86.88 (at 34 min) -> 88.25: +1.37 pts, but the gain came from golf on r3 (see above), not the new routes.
- CCS: 86.44 -> 86.44: $0.15 post-best spent on up-to-bisimulation / grind / `or_else_symm` probes for 0.0 gain (the largest dead spend of the three).
So the finish rule bought +1.4 on VC and ~0 on Core/CCS; total ~$0.2 over the 3 runs went after 'good enough'. DeepSeek's reaction is revealing: it computes the exact budget, e.g. Core "Budget: $0.3587 spent, $0.1413 remaining (28%). I need to spend it down to <=10% ($0.05) before finishing", then "$0.0525 left = 10.5% ... refused (just barely!)... one more small probe". To satisfy the new-route test it even re-compiled the *baseline* as a candidate (route r1 registered with 0 attempts; the harness did not count it) and probed a one-token variant of the original (#36 223 tok, 33.49) to register r1, then added a throw-away lemma-family draft (#37, 80.25) to register r3, only then did `arena_finish` confirm (61 min). That is compliance-driven overhead (about $0.02-0.04), not exploration.

**Compactions and memory.** 3 compactions per run (session-level; the cost summary counts 5 "compaction" settles; I only see 3 compaction entries in each session, the other 2 are unexplained, possibly split-turn helper requests), each at ~200-215K context tokens (tokensBefore 201K-215K), each costing ~$0.016-0.028; compaction total $0.064-0.067 = 14% of spend (largest non-compile category). Summaries grow 4.7K -> 22.7K chars (Core 5.5K, 13K, 22.7K; VC 8K, 15K, 16.8K; CCS 4.7K, 12.6K, 16.4K). After each compaction the harness injected an `arena-memory` custom message (1.27-1.67K chars: best verified candidate, route/idea tallies with attempts and best proxy, latest failures) 10-110 seconds later (Core memory at +11s, +52s, +27s; CCS +30s, +110s, +62s). Post-compaction behaviour: of 9 compactions, 4 first re-read source/declarations (Core #1 `arena_source, arena_find`; Core #2 `arena_find, arena_source, arena_declarations`; CCS #1 `arena_find x2`; VC #1 `arena_candidate` to re-fetch the incumbent) and 5 went straight to `arena_probe`. No duplicate drafts occurred, so re-reading cost a few turns (~$0.01-0.02 each) not redone proofs. Memory messages carry "Best verified candidate: #26 ... arena_candidate #26 returns its source", which the model used immediately (VC and Core fetch the incumbent via `arena_candidate`). Failed-draft lessons survive only through the 'Latest failures' list and the model's own compaction summary.

## 4. Harness quirks seen

1. Finish-rule spend-down gaming (all 3 runs). The model reads `remaining_fraction` and deliberately burns budget to reach <=10% (Core: 10.5% remaining -> refused "just barely", needed another probe). The "new route" check is fingerprint based and demands a *compiled* proof: re-compiling the original baseline did not register route r1 (Core); a 1-token variant of the original (#36, 33.49) did; similarly Core #37 (80.25) and VC #64 (85.05) exist only to satisfy the gate. Dead spend after best: Core $0.027, VC $0.029, CCS $0.150 (CCS up-to-bisimulation / grind / `or_else_symm` probes, 27 requests, no gain; the CCS refusal sequence (18:12-18:29) overlapped the 17:59 exploration-credit change, but the model still reasoned "the harness wants a *compiled* proof on a new route", so I cannot see the A/B/C credit having changed its behaviour).
2. Idea attribution lag: VC candidates 41-56 min labelled i4 before i4 existed (declared 57 min); CCS has idea ids i1..i8 plus free-form labels (`upto_C`, `grind-bodies`) - labels from the `idea=` argument are not validated.
3. Route accounting: Core r1/r3 and VC r4 are "attempted" by 1-8 drafts that are not true new strategies (r1: 1 attempt, 33.49). r4's fingerprint absorbed later drafts ("#61/#62 did not count as a new route", model note), so the finish check can pass or fail on fingerprint luck, not on strategic novelty.
4. Compaction cost and lag: 3 compactions/run at ~200-215K tokens (config `compact_at_tokens` 200000, keep 40000) costing 14% of spend; arena-memory message arrives 11-110 s after the compaction (CCS #2: 110 s) as a separate step; the summaries grow to 16-23K chars. Cost summary shows 5 compaction settles for 3 compactions (unexplained extras).
5. Infrastructure/latency: CCS wall time 125 min for 78 turns (Core 62, VC 63 min for similar turn counts): arena_probe took 48-128 s whenever the Lean session was `cold` or rebuilt; warm calls take 0.6-2 s (lean-session.log / campaign log). Two provider errors (VC `Request timed out`, CCS `terminated`) were each retried successfully (settled cost unknown for those: "unresolved" $0.10 / $0.046 shown in summary.txt, so spent can be $0.46+0.10 nominal while cap accounting says no overshoot).
6. Summary stats: `tool errors 1: arena_probe` in Core summary.txt is not visible in the trace (no isError tool_result), so error counting differs between summary and trace; VC's single true tool error was an `arena_source` for a hallucinated name (`Continuous.inner`).
7. The context-bound fix (16:11) applies to later runs; Core (started 15:13) and VC (15:42) predate it but showed the same compaction pattern as CCS (16:45), and no `length` stops occurred in any of them, so it did not matter for DeepSeek's outputs here.

## 5. Why DeepSeek wins (evidence)

Scoreboard (pilot, $0.50 soft cap): DeepSeek 86.07 / 88.25 / 86.44 (mean 86.92); Qwen 86.02 / 87.32 / 78.43 (CCS run interrupted at $0.09); Luna 85.11 (stopped `error_loop` at $0.17) / 66.13 / 75.62. Versus priors: v6 first runs at $0.10: Core 83.88 (DeepSeek +2.2), PhysLib 81.07 (+7.2); v5 hybrids: Core 87.10 (DeepSeek -1.0), CSLib 84.52 (+1.9). Honest framing: on Core and VC DeepSeek only edges Qwen (+0.05, +0.93); the clear separation is consistency (all three >=86, no early stop, no stall) plus a 9-22 point gap to Luna.

Concrete traits:
1. **Thinks 5-7K tokens per turn, and spends it on designing the proof rather than on tool churn.** DeepSeek used 67-89 turns at ~5.7K output tokens/turn; Luna used 104-171 turns at ~0.8-1.1K, Qwen 88-98 turns at 2.2-3.4K. Luna's cap was 29-57% bookkeeping (30-78 finish/state/idea turns) and its VC result 601 tokens (reference 851); DeepSeek's bookkeeping is 2-7%. The same dollars bought deeper per-draft reasoning instead of more turns.
2. **Finds the winning global route in the first 2-5 minutes ($0.02-0.04), before any golf.** Core turn 1 reasoning: "Let me focus. I want to find a slick proof... Route A (equational): sigma' = updatedStates sigma ks vs (UpdateStatesUpdated Hup); sigma'' = updatedStates sigma' ks' vs' (InitStatesUpdated Hinit)" then candidate #2 (77.0) dropped the induction and 90% of heartbeats. VC: "Key idea: maybe there's a much simpler approach using existing lemmas. Let me search the source" -> found `Continuous.integral_pos_of_hasCompactSupport_nonneg_nonzero` and replaced the 121-line WithLp/Cauchy-Schwarz proof (75.8 at $0.04). CCS: replaced the 58-line case analysis with `refine ⟨ChoiceBisim, .choice h, ?_⟩` (72.3 at $0.017), then discovered symmetric-simulation via `HomBisimilarity.symm_simulation` (79.1, 16 min). All three chains show a library-lemma search (`arena_find` 8-17 calls, `arena_declarations`) before the first draft.
3. **Explicit score arithmetic that tells it where points remain.** Core turn 8: "335 heartbeats is already 92% reduction... Token: 137 vs 224... Since heartbeats are nearly maxed, focus on tokens. Each token = 0.149 pt. Saving 10 tokens = 1.49 pt." VC turn 1: "exchange rate: 100 hb = 0.279 pt, 1 token = 0.039 pt. So 100 hb = 7.15 tokens". It then switched to token golf after the first rewrite, as the diffs show (every later step is a token reduction; HB barely moves). 49/58/56 of its 67/89/79 turns mention hand token counts or exchange rates.
4. **Line-by-line token accounting to choose what to attack.** CCS after refusal: "token budget breakdown: intro h 2, rw 4, refine 27 (symm 15), rintro 11, cases/rename 5, bodies 35 ... the ~26 tokens for scaffolding is the biggest single chunk" -> led to `ChoiceBisim.rec (.choice ·.symm) (.bisim ·.symm)` style and `And.imp Tr.choiceL ChoiceBisim.bisim`, 125 -> 85 tokens.
5. **Small incumbent-relative edits, batched and hypothesis-driven.** Each `arena_probe` carries ~2.3 drafts; each new best descends from the previous best in 13/13 (CCS), 10/21 (VC), 5/11 (Core) steps, the rest from a near-best sibling in the same batch; changes are typically 1-5 lines, and failures are diagnosed correctly ("`rw` can't rewrite inside the integral's lambda", "exact does NOT create a goal for the ?_ ... refine is special", "the nested `fun hb => ChoiceBisim.rec ...` needed a motive"). Zero duplicate drafts in 264 drafts, including across 9 compactions.
6. **Uses cost-free signals correctly.** `arena_profile` called 3/7/2 times to target heartbeats; it hand-checks the lowest-token count; it reads `tokens_vs_lowest_seen` from the finish review. It never hit the 32K output limit (max 24.3K), had no malformed tool calls (0-1 tool errors), and no stall/`error_loop` (Luna Core).
7. **Obeys and exploits the finish rule rather than fighting it.** It computes the spend-down needed (28% left -> "I need to spend it down to <=10%"), gets 3-4 refusals and still finishes correctly each time at 61-104 min, and in VC converted the extra budget into +1.4 pts. Cost: dead spend in CCS ($0.15) and Core.
8. **No true plateau within the cap.** VC improved 22 times and CCS 14 times; the last ~60% of spend still produced +0.02 to +2 pts. This suggests a larger cap would continue to pay on VC/CCS (score density: +0.04 at the very end) but not on Core (86.05 at $0.20 -> 86.07 at $0.43).

Risks / caveats for the 'DeepSeek wins' claim: (a) Luna's low scores include an `error_loop` stop and heavy bookkeeping, partly harness interaction (finish/state tools) rather than pure capability; (b) Qwen is within 0.05-0.9 pts on 2 of 3 tasks, so the Qwen gap is not yet statistically meaningful at n=1 per task; (c) local `proxy` is not the official Arena score ("calibration pending"); (d) the CCS run overlapped a harness change at 17:59 and ran under heavy Lean contention.
