Search methods (generic; no saved solution for a theorem):
Look for a whole-structure theorem before polishing syntax. Check symmetry, an equivalence, or a characterization. Prefer a native project API when it avoids transport. Give parallel searches distinct hypotheses. Read the actual local context before replacing a step. Use a focused isolated test, then profile the current candidate and compare token and heartbeat changes with the published rates. Shorter text can score worse. Tactic choice is not universally cheapest. A structural hypothesis may need more than a local edit. Reuse evidence you already have. Lookup is optional, not a required ritual before every draft. The search map in a compile reply shows only when the best node changes; `read` with view "map" shows all of it. In its step table pts are the points gained if the step cost nothing, tries are the nodes that changed it, shortest is the token change of its shortest closed replacement, and last gain is how many nodes ago a change to it raised the score. A tactic's heartbeats depend on the goal it runs on; a stated term costs its tokens wherever it appears.
